# 반복업무 자동화: 현황과 다음 단계 (2026-11-07)

기준: 클로드 채팅의 자동화 계획(docs/반복업무-자동화-계획.md) + eunbit 저장소 조사(docs/eunbit-저장소-조사.md)

## 업무별 현황
| # | 업무 | 상태 | 막힌 것 / 필요한 것 |
|---|---|---|---|
| 1 | 알림장 작성 | 자동화 불가(사진·에피소드 필요). 작성 때 일지용 데이터 누적만 가능 | 누적용 .md 형식 정하기 |
| 2 | 일지 | 주 1회(금) 일괄로 확정. 누적본으로 초안 | 누적 시작 전이라 초안 불가 |
| 3 | 월말 관찰일지 | 누적본에서 아이별 추출. 한그루 입력은 붙여넣기 | 관찰일지 양식 |
| 4 | 아침돌봄수당 | 방법 모름. 대화·저장소 모두 흔적 없음 | 샘플 파일, 계산 규칙 |
| 5 | 일당직표↔연차달력 | 두 도구가 Apps Script 웹앱임을 확인. 규칙·소스 미확인 | Apps Script 소스 또는 시트, 연장반 대체 규칙 |
| 6 | 한그루 연차↔연차달력 | 한그루 화면 읽기 필요, 시험 전 | 한그루 접근 방식 |

## 판단
- 지금 바로 시작할 수 있는 것은 1~3번(알림장 누적 → 주간 일지 → 월말 관찰일지). 외부 접근이 필요 없다.
- 5번은 크롬으로 화면을 읽기보다 Apps Script 안에 2주마다 도는 확인 기능(시간 트리거)을 넣는 쪽이 더 안정적일 가능성이 높다. 단 소스를 봐야 확정할 수 있어 가정이다.
- 4번은 정보 없이 만들 수 없다. 추측으로 쓰지 않는다.
- 6번은 가장 불확실하다. 1~5번 이후에 한그루 접근 시험을 한다.
- AI 오피스가 어떤 플랫폼인지, 에이전트가 PC·브라우저에 접근 가능한지는 아직 모른다. 이게 정해지기 전에 SOP를 6개 다 쓰면 다시 써야 할 수 있다.
