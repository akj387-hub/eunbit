## 2번 판단: 매일 일지 vs 주간 일괄

결론: 놀이지원·지원계획은 일주일 단위로 봐야 정확함. 매일 쓰는 방식은 알림장에 지원 내용이 없을 때 일지에서 지어내거나 다시 써야 함 → '추측 대신 실제 행동 기록' 원칙과 충돌.

| 방식 | 장점 | 단점 |
|---|---|---|
| 매일 확인·작성 | 그날 기억이 생생, 밀리지 않음 | 지원·계획이 안 나오면 재작성. 주간 흐름·발달 변화 못 봄 |
| 주 1회 일괄 (금요일) | 한 주 흐름·발달 변화·다음 주 지원 방향을 근거 있게 작성. 중복 방지 쉬움 | 한그루에 매일 제출해야 하는 규정이면 불가 |

추천: 주 1회 일괄 + 알림장 쓸 때 "일지용 데이터"를 같이 저장
- 내가 알림장을 쓸 때 놀이명(실내2·바깥1), 영아 모습, 교사 지원을 별도 .md에 누적 → 일지는 알림장을 다시 읽지 않고 이 누적본을 사용
- 알림장에 지원 내용이 없으면 에피소드를 줄 때 한 줄만 추가 ("이날 이렇게 도와줌")
- 매일 제출 의무가 있다면: 매일은 그날 사실만 짧게(초안), 금요일에 전체평가·지원계획 보강

미확인: 한그루 일지를 매일 제출해야 하는지, 알림장에 지원 내용이 평소 들어가는지.

## 자동화 방식 (현실적인 수준)

완전 무인 자동화는 어려움. 가능한 수준은 "PC 열린 시간 + 한마디 트리거 + 제출 전 확인".

A. 반자동 (바로 가능, 가장 안정적)
- 알림장 작성 때 누적한 데이터로 일지 초안 생성 → 한그루에 붙여넣기
- 월말 관찰일지도 같은 누적본에서 아이별로 추출

B. 크롬 확장 연결 (시험 필요, 보장 못함)
- 16:30 PC 켜고 한그루 로그인 상태에서 "일지 써줘" 한마디 → 내가 한그루 알림장을 읽고 일지 칸에 입력
- 예약 작업(평일 16:40)도 가능성은 있으나 PC·크롬이 켜져 있어야 하고, 한그루 입력 칸이 자동 입력을 받는지는 해 봐야 앎
- 제출 버튼은 선생님이 직접 누르는 방식 권장 (오류·개인정보 방지)
- 영아 정보가 담긴 화면을 AI가 읽으므로 어린이집 지침 확인 필요
